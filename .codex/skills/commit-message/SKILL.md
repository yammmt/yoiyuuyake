# コミットメッセージガイド

コミットを行う際の、コミットメッセージの規約を記します。

## 全体

[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) に従い、以下の形式で記します。

```text
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

## 見出し

見出しとは、メッセージの一行目を意味します。

- Conventional Commits の冒頭部を除き、 50 字以内の英語で、命令形を用いて記します。
- 英語の大文字は、固有名詞 (例: "CI") を除き、用いません。
- 冠詞は省略します。

## 本文

変更の理由や実装の理由など、他の人が後から `blame` をした際に十分な情報を提供するようにします。
"fix typo" のように、見出し部分だけで十分な情報を提供できる場合、本文は省略して構いません。

- 行の長さは、最大で 72 字です。
- 見出しと本文の間には、空行を一行挟みます。
- 必要に応じ、空行を挟んで段落を分けて記します。

## フッター

co-author 情報は用いません。

## `fixup` コミット

作業ブランチ上のコミットに対する修正は、 `git commit --fixup=<対象コミット>` を用います。
このコミットは、これまでの規約、特に Conventional Commit の形式とは矛盾しますが、許容します。
これは、 `fixup` コミットは後に消滅する前提のコミットであり、 Git の正史には残らないコミットであることを考慮した判断です。
