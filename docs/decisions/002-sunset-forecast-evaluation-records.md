# ADR 002: 日没時点の予報と主観評価の記録

## 状態

採用（2026-11-04）。実装方式は未決定。

## 背景

初回デプロイは完了している（利用者からの報告）。現在の夕焼けスコアは実際に観察した結果との対応を検証できていない。
評価式の改善に向け、予報の入力気象データと利用者本人の主観評価を対応付けて蓄積する。
本決定はMVPの非対象としていた記録・現地観察を、初回デプロイ後に追加する #33 の方針である。

主観評価の入力は毎日あるとは限らず、観察後になることもある。
入力時に過去の気象データを取得しても、日没時点で取得できた予報と同じ情報であるとは扱えない。
予報の取得を主観評価の入力から独立させ、取得タイミングをそろえる必要がある。

## 決定

- 事前に登録した地点について、毎日その地点の当日の日没時刻に最新の予報を自動取得・保存する。
- 日没前後のスコア計算に使った気象データを保持し、後日の取得データで置き換えない。
- 利用者本人が観察した日の記録に主観評価を手動で追記する。評価の入力日時と実際の観察日時・時間帯を区別する。
- 未観察の日も予報の記録は残し、主観評価は未入力とする。未観察を低評価や0点として扱わない。
- 評価式と主観評価との対応の検証には主観評価がある記録を用いる。
- 記録は永続保存し、分析用に取り出せるようにする。保存・編集の操作は利用者本人に限定する。

保存する情報の範囲は次のとおりとする。具体的な形式は実装前に決める。

| 区分 | 保存する情報 |
| --- | --- |
| 地点 | 地点名、緯度・経度 |
| 予報の日時 | 対象の日没日時、実際の予報取得日時 |
| 気象 | 計算に使った気象データ一式、各データの対象時刻、使用した気象モデルを識別する情報 |
| 評価式 | Gradient・Dramaticのスコア、計算式のバージョン |
| 観察 | 実際の観察日時・時間帯、主観評価、任意のメモ、評価の入力日時 |

## 理由

まずは日没時点で取得できる気象予報と実際の夕焼けの見え方を対応付け、評価式を検証する。
数時間前に外出を判断するための予報の有用性は、別の検証課題とする。
自動取得により、主観評価の入力頻度や入力時刻に左右されず、同じ基準で予報を確保できる。
入力気象データを残すことで、新旧の評価式を同じデータに適用して比較できる。

## 結果と制約

- 日没時点で取得する予報も、実測の気象データとは限らない。主観評価との差には、気象予報の誤差と評価式の問題の両方が含まれる。
- 取得時刻をそろえても、気象モデルの更新時刻や予報の新しさまでそろうとは限らない。
- 日没の3時間前と日没時点で予報がどの程度変化するかは未検証である。
- 未観察の記録だけではスコアの当たり具合を直接検証できない。また、観察した日に偏りがあれば、検証結果にも偏りが生じうる。
- 定期取得・保存と、本人だけが評価を追記できる仕組みが必要になる。本ADRではクラウド資源の作成や公開設定の変更は行わない。

## 未決事項

- 登録地点の数、登録・変更の操作方法。
- 主観評価の項目、尺度、各段階の基準。Gradient・Dramaticに対応する二項目と0〜4の尺度は提案段階であり、未確定。
- 保存先、データ形式、入力フォーム、分析用の出力形式。
- 定期実行の方式、日没時刻に対する許容遅延、取得失敗時の再試行・欠測の扱い。
- 本人限定のアクセス制御の方式。
- 利用するサービスの費用、停止・削除方法。課金資源を採用する場合は、作成前に確認する。
