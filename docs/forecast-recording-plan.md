# 予報の自動取得・保存の実装方針

2026-11-08 時点の #54 の決定事項を記録する。
設計の前提は [ADR 002](decisions/002-sunset-forecast-evaluation-records.md) とする。
本書は実装前の方針であり、クラウド設定や動作確認の完了を示すものではない。

## 地点の管理

対象は利用者の生活拠点1か所とし、Firestore の `locations/home` に保存する。
項目は `name`、`latitude`、`longitude`、`enabled` とする。
初回登録と変更はコンソールから手動で行い、管理画面や専用コマンドは作らない。
実際の座標は公開文書やリポジトリに記載せず、地点と記録へのアクセスを本人と自動取得処理に限定する。

## 実行ルール

Cloud Scheduler から毎朝予約処理を呼び出す。
予約処理は地点設定を読み、当日の日没時刻を計算し、Cloud Tasks に取得処理を予約する。
予約処理と取得処理は専用の Cloud Run サービスで実行し、定期的な日没時刻の確認や日没までの待機は行わない。

| 処理 | 初回実行 | 失敗時の再試行 |
| --- | --- | --- |
| 当日の取得予約 | 毎朝6:00（日本時間） | 失敗後30分間隔で最大2回 |
| 予報の取得・保存 | 当日の日没時刻 | 失敗後10分間隔で最大2回 |

いずれも初回を含めて最大3回とする。
予約処理を再実行しても、同じ地点・対象日の予約は重複させない。
実際の取得時刻を記録し、予定時刻と区別する。
取得・保存の全試行が失敗した日は欠測とし、推測値を保存しない。失敗理由はログに残す。

## 記録と上書き防止

記録形式は ADR 002 に従い、記録IDは `home_YYYY-MM-DD` とする。
対象日は日本時間で決め、Firestore の `records/{記録ID}` に保存する。
取得時点の地点情報、日没日時、予報取得日時、提供元・モデル、計算に使った気象データと対象時刻・単位、評価式のバージョン、Gradient・Dramatic スコアを保持する。
`observation` は `null` で作成し、主観評価の入力は #55 で扱う。

予報の取得、必要なデータの検証、スコア計算が成功してから、完成した記録を1回の書き込みで新規作成する。
処理途中や失敗時の記録は作らない。
記録が存在すれば保存まで成功したものとして扱い、再実行では上書きしない。
追加のロックや同時実行の管理は設けない。
地点設定を変更しても、過去の記録内の地点情報は変更しない。

## 今後の作業

日時の保存形式や入力値の検証、具体的な権限とサービス設定は実装時に整理する。
費用と停止・削除方法を確認してから、利用者本人がクラウド操作を行う。
`enabled: false` による対象除外、定期処理の停止、登録済み予約の削除、保存データの削除は別の操作として扱う。
